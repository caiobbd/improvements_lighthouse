# Phase 08.1: Improving context from attributes - Context

## Locked Decisions

- Phase sequencing:
  - This is an inserted phase after Phase 8, independent from completing Phase 8.
- Delivery sequencing:
  - First deliver backend + table foundations.
  - Then deliver threshold line rendering + custom alarm UI.
- Table/UX:
  - Chart sensor table must support vertical + horizontal scroll inside the table area only.
  - Sticky header is required.
  - First column (sensor name) must stay visible (sticky first column).
  - Missing values render as `N/A`.
- Columns and filters:
  - App-level column filter is global in behavior (not per-user personalization in this phase).
  - Runtime selection restores from localStorage on reload.
  - Repo-versioned default columns are source-controlled.
  - Column defaults will be tuned after user trials.
- Data semantics:
  - `last value` = last point inside current chart range.
  - `-1d AVG` is always computed from timeseries data (never taken from sub_attributes).
  - Threshold line rendering must not be blocked by unit mismatch.
  - Show threshold unit and base sensor unit independently when available.
- Threshold line behavior:
  - HiHi + LoLo are red dashed lines.
  - Hi + Lo are yellow dashed lines.
  - Threshold lines are off by default and user-controlled by table toggles.
  - Table uses one toggle per threshold column per sensor row.
  - Toggled thresholds are rendered as additional rows in the table.
  - Threshold rows show `N/A` for unavailable context fields.
  - If a second tag is added to a chart, threshold lines are removed from that chart.
  - If the chart returns to one tag later, thresholds remain off until user re-enables.
- Custom alarms:
  - Right-click option must be available for all sensors: `Create custom alarms`.
  - One custom pair per sensor: `Custom-Hi` and `Custom-Lo`.
  - Custom alarms coexist with system thresholds (separate selectable columns/lines).
  - Persist audit/history data:
    - `created_date` (first creation),
    - `updated_date` (last user edit),
    - `version_n`,
    - stored values for `Custom-Hi` and `Custom-Lo`,
    - user fixed as `unknown` in this phase.
  - Keep version history capped at 20 versions per attribute.
- Persistence:
  - Use SQLite only in this phase.
  - SQLite filename should be custom-alarms related.
  - Export/import is deferred.
  - SQLite location approved: `backend/app/data/custom_alarms.db`.
- Duplicate normalization rule (sub_attributes):
  - Prefer non-null value.
  - Tie-break by `is_external = false`.
  - Final tie-break by newest `updated_at`.
- Threshold row format:
  - Approved label format: `{Sensor Name} | {ThresholdName}`.
- Column manifest format:
  - Repo default-column manifest is JSON.
- Custom alarm key scope:
  - Key is `attribute_id` only (global reuse across items that share attribute_id).

## Data Findings To Drive Implementation

- Current public `/item-attributes` response is reduced and does not expose `sub_attributes`.
- Raw workspace attributes for `MV30-HBG-1120B` do contain `sub_attributes`, including Hi/Lo/HiHi/LoLo/Minimum/Maximum/Target and derived entries.
- Duplicates are common in sub_attributes (often paired `is_external=true/false` rows), requiring deterministic normalization.
- Coverage is partial across sensors (not every sensor has all thresholds).
- `timeseries-batch` cold-path cost is high for full equipment tag sets; warm path is acceptable. Incremental/cached strategy is required.
