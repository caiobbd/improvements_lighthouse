# Phase 9 Plan 01: Shell, Sidebar Boundaries, and Metadata Relocation

## Objective

- **What:** Replace the rejected single-sidebar shell with explicit app-sidebar, equipment-sidebar, workspace, System Info modal, and hidden right-rail contracts.
- **Why:** The acceptance gate cannot pass while global navigation, current-page navigation, metadata, and workspace anchors are mixed in the same layout surface.
- **Output:** A stable shell foundation that downstream plans can use without re-solving navigation or metadata placement.

## Scope Boundary

This plan owns only shell/sidebar structure, shell state, System Info modal placement, hidden right-rail scaffolding, baseline reset for the shell/header/sidebar surfaces it touches, and preservation of existing Charts anchors.

This plan must not implement browser-tab styling, quick-range controls, gear-menu exactness, chart-card action behavior, or plot-density changes. Those belong to 09-02 and 09-03.

- **App/sidebar order:** manual check confirms primary app sidebar is leftmost and equipment tree is immediately right of it.
- **App auto-collapse:** manual check confirms equipment expansion collapses primary app sidebar to an icon rail.
- **Right-sidebar future slot:** DOM/CSS inspection confirms placeholder exists but no visible right rail appears by default.
- **Metadata relocation and visual baseline:** manual check confirms `Environment` and `Backend Contract` appear only in System Info modal, not persistent header/top controls, and the shell keeps the Lighthouse light palette without dark header blocks.
- **Regression guard:** `node --check frontend/charts/app.js` passes and Charts bootstraps without console-breaking runtime errors.
