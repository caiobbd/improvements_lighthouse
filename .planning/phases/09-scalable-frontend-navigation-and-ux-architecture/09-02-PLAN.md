# Phase 9 Plan 02: Top Controls Exactness and Legacy-Control Removal

## Objective

- **What:** Repair the rejected top-control model into the locked browser-tab row plus compact top-right toolbar.
- **Why:** The acceptance gate is exact: extra controls, wrong labels, stacked legacy rows, or a non-exact gear menu fail the phase.
- **Output:** A deterministic top-area control contract ready for final chart-card remediation in 09-03.

## Scope Boundary

This plan owns only the tab row, top-right toolbar, date filter, reload/frequency controls, grid icons, settings gear, and removal of duplicated legacy top controls.

This plan must not change shell/sidebar structure from 09-01, chart-card help/action overlay behavior, plot density, chart draw height, or right-rail activation.

<defects_to_fix>
- Tabs were previously not guaranteed to be isolated from toolbar controls as a browser-like row.
- `+` page creation must be a tab immediately after the last tab, not a separate `New Page` button.
- Legacy page actions (`New Page`, top `Actions`, inline `Edit`/`X`) must not remain as visible top controls.
- Time controls must not use the old preset/date-input rows; they must be compact top-right quick-range buttons.
- Reload/frequency must be a coupled reload icon plus toggle, with manual dropdown visible only while toggle is on.
- Grid controls must be icon-only and limited to `2-col` and `3-col`; no text-heavy or extra grid modes.
- Gear menu currently risks failing exactness due to extra `System Info` and non-exact labels.
</defects_to_fix>
